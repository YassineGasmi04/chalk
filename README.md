# CHALK - the AI pundit that draws on the pitch

> Entry for the Microsoft x Premier League **Inside the Game: Developer Hackathon**
> (challenge: *The Synthetic Match Insights Engine for Premier League Studio*).

TV pundits don't just talk about a moment. They pause the match and draw on it:
an arrow for the run, a circle on the pressing trap, a shaded zone for the gap.
CHALK makes a team of AI agents do that automatically for every key moment of
a live match, checks every claim against the data, and redraws the story
differently for each viewer.

**Data statement:** every club, player and match in this repository is fictional
and generated by code. No real Premier League data or footage is used.

## Pipeline

| Stage | What happens | Where |
|---|---|---|
| **Ingest** | Seeded synthetic match engine streams football-realistic events live (passes, carries, take-ons, pressures, tackles, interceptions, shots, saves, fouls, cards, subs, formation changes) with a 22-player position frame on every event | `chalk/sim/` |
| **Interpret** | Deterministic code turns events into team and player stats, xG, pass difficulty, PPDA, field tilt, top speeds, and a minute-by-minute **Match Pulse** (dominance and control vs chaos) | `chalk/stats/state.py` |
| **Spot** | Plain code decides which moments matter (goals, big chances, red cards, press surges, momentum swings, tactical shifts, record passes and sprints) and attaches the facts, evidence and coordinates | `chalk/stats/moments.py` |
| **Explain** | A crew of four agents on **Microsoft Agent Framework** explains *why* each moment mattered, draws it on the pitch, fact-checks it and personalizes it (see below) | `chalk/agents/` |
| **Render** | Broadcast-style web app: 3D gantry camera or flat tactical view, live stats, Match Pulse timeline. When the crew airs an insight, the broadcast freezes on the moment, the Telestrator's drawings appear stroke by stroke, and a lower-third shows the verified analysis. Also exported as a timed overlay feed (`chalk.overlay/1`). | `web/`, `data/match_4_overlay.json` |
| **Ask** | Viewers ask the studio anything, typed or **spoken**, in English, French or Arabic. A **Studio Q&A agent** answers through the **CHALK MCP server**, which only sees the match up to the minute the viewer is watching (no spoilers); VAR checks every number against the tool results before the answer is shown | `chalk/agents/qa.py`, `chalk/mcp_server.py` |
| **Personalize** | Watch as **Analyst** or **Fan**, in **English, French or Arabic** (right-to-left), pick **your club** (its moments are flagged "Your club") or **follow a player** (a ring follows them, their live stat card fills in, their moments are flagged "Your player") | `web/studio.js` |

### Design rule: code owns the numbers, AI owns the words

Every number on screen comes from the Interpret layer. Agents may only use
values from a moment's `facts`; the VAR agent rejects any claim that doesn't
match them.

## The virtual studio crew

```
Spotter (code) -> Producer (code) -> Analyst -> Telestrator -> VAR --stands-------> Personalizer -> on-air card
                                       ^                        |
                                       +------- overturned -----+   (one retry, then a rulebook-safe fallback)
```

Each agent is an `agent_framework.Agent`; each moment runs through an Agent
Framework `Workflow` whose conditional edge lets VAR send work back.

At full time a fifth agent, **Recap**, writes the match recap from a full-time fact sheet
computed by code (result, goal timeline with what each goal did to the score, turning
point, player of the match picked by code). It goes through the same VAR and Personalizer.

| Agent | Job | Output |
|---|---|---|
| **Analyst** | Explains why the moment matters. Every claim must cite the fact keys that prove it. | headline, 2-3 sentence story, claims with `fact_keys` |
| **Telestrator** | Turns the story into 2-5 drawings, like a pundit's touchscreen pen | arrows, player rings, links, shaded zones, in pitch metres |
| **VAR** | Nothing airs without it. A deterministic **rulebook** checks every number against the fact sheet, bans invented context ("record", "this season"...) and rejects drawings that aren't anchored to real player positions; then the VAR **judge** agent checks that each claim actually follows from the facts. It can overturn and send the card back to the Analyst. | verdict + issues |
| **Personalizer** | Rewrites the verified insight for an **analyst** and a **casual fan**, in **English, French and Arabic** | 6 captions per moment |

Safety nets, so the broadcast never waits and never airs an unverified claim:
- overturned twice: VAR airs a rulebook-safe version built only from the fact sheet
- model down or rate-limited: retries with back-off, then a rule-based pundit with the same JSON contract; after three failures in a row a circuit breaker stops waiting on the model
- every model answer is recorded in `data/cache/agent_calls.json`, so the demo replays identically and costs nothing to re-run

Outputs:
- `data/match_4_insights.json`: one card per aired moment (story, claims, drawings, 6 captions, the full VAR history and an agent trace)
- `data/match_4_overlay.json`: a timed, machine-readable overlay feed (`chalk.overlay/1`) a broadcast graphics engine could render: caption and telestration cues with start/end times on the match clock and shapes in pitch metres

### Run the crew

```bash
cp .env.example .env          # then fill in your Microsoft Foundry endpoint, key and deployment
python scripts/run_pundit.py  # uses the model in .env
python scripts/run_pundit.py --offline   # rule-based crew, no key needed
```

## Ask the studio (MCP)

The match data is exposed as a real **Model Context Protocol** server, `chalk/mcp_server.py`,
with seven tools: `match_status`, `team_stats`, `player_stats`, `top_players`, `key_moments`,
`moment_details` (including the crew's aired analysis) and `match_flow`. Every tool is pinned
to a **time cutoff**, so an agent answering a viewer at the 30th minute cannot see the 80th.

```
viewer question --> Studio agent (agent_framework.Agent, tools = the CHALK MCP server at the viewer's minute)
   (text or voice)        |  calls match tools over MCP, writes a 1-3 sentence answer
                          v
                    VAR rulebook: every number must appear in a tool result, no ids or key names,
                          |       no outside context ("this season", "record"...)
                          |  overturned? one retry with VAR's notes
                          v
                    answer on air + the tools it used, the player it talks about ringed on the pitch
                    (if the model fails twice: a rule-based answer built from the same tools)
```

- `POST /api/ask {question, t, seed, lang, persona}` returns the answer, the tool calls, the VAR verdict and timing.
- The same server is mounted over **streamable HTTP at `/mcp/`**, so any MCP client can use it, and
  `.vscode/mcp.json` connects **GitHub Copilot in VS Code** to it: ask Copilot Chat
  "who has been the fastest player?" and it queries the match through CHALK's tools.
- Standalone over stdio: `python -m chalk.mcp_server --seed 4 --cutoff 1800`.
- From the terminal: `python scripts/ask_studio.py "How is Mensah-Cole doing?" --minute 30 --lang fr`.
- Answers are cached in `data/cache/qa_calls.json` (per question, language, persona and match minute).

## Live mode

`chalk/server.py` (FastAPI) streams the match **as it happens** over Server-Sent Events and
runs the whole pipeline live: events are released on the match clock, `MatchState` and the
Spotter update on every event, and the studio crew runs on each aired moment the instant it
is detected. Insights go on air when the crew finishes (typically 1-3 match seconds later).
Recorded model answers are reused, so a demo costs nothing; without a model configured the
server replays the recorded crew.

```bash
uvicorn chalk.server:app --port 8000   # then open http://localhost:8000 and press "Watch live"
```

| Endpoint | What |
|---|---|
| `GET /api/live?seed=4&speed=10&ai=auto` | the live feed: `event`, `pulse`, `moment`, `insight`, `recap`, `end` messages |
| `GET /api/health` | which model the crew uses |
| `POST /api/ask` | ask the studio a question at a match minute (MCP tools + VAR) |
| `GET /api/new-match` | a fresh seed: a match nobody has seen, explained live by the crew |
| `/mcp/` | the CHALK match data MCP server (streamable HTTP) |
| `GET /api/match/4/insights` | the recorded insight cards |

## In the app

- **A floodlit stadium**: mown two-tone grass with grain and goalmouth wear, four floodlight pools and the matching four soft shadows under every player, stands full of fans in each club's colours, a floodlit roof, 3D goals with nets, corner flags, and LED boards that scroll and switch to the scorer's colours (with camera flashes in the stands) after a goal
- **Three cameras**: Broadcast (gantry), **Follow cam** (zoomed, panning with the ball like a TV match camera) and Tactical (top down), with animated moves between them; long passes and shots fly in an arc with a shadow and a trail
- **Analytics layers** (Layers button on the pitch), all computed live in the browser from the positions: **space control** (exact Voronoi cells and each team's share of the pitch), **team shape** (outfield block, width x depth, back-line height), **heatmaps** (team, or the player you follow), **pass network** (last 15 minutes) and **run trails**
- **Clickable players**: hover to highlight, click for a player card (live stats, top speed, a heatmap so far) with *Follow* and *Ask the studio*
- **Win probability**: a live Poisson model on each team's xG so far, adjusted for red cards, computed by code
- **Event cards**: shots, fouls, cards, subs and top speeds stack in on the pitch as layered cards

- **Ask the studio**: a chat tab with suggested questions, a microphone for spoken questions and spoken answers (Voice on); each answer shows its VAR badge and the MCP tools it called, and the player it talks about is ringed on the pitch
- **New match**: simulates a match nobody has seen (a new seed) and the crew explains it live, start to finish
- **Trust report** (Studio crew tab): claims checked, facts cited, how many times VAR overturned the AI, rulebook versions aired, drawings kept, model calls, Q&A answers sent back, and median / p95 latency per agent

- **Welcome screen**: what the four agents do, then *Watch live*, *Watch the match* or *AI highlights in 2 minutes*
- **AI highlights**: plays only the moments the crew analysed, drawings and all, then the full-time recap
- **Match Pulse**: who is on top minute by minute, chaotic spells, and an amber marker for every AI insight (release the scrubber on one to replay it)
- **Voice**: reads each insight aloud in English, French or Arabic (browser speech synthesis)
- **Full-time recap**: result, the AI's verified recap, every goal and what it did to the score, player of the match, a shot map sized by xG, and a button to replay the turning point
- **Broadcast graphics**: an animated goal stinger in the scoring team's colours (scorer, xG, shot speed, distance) with chalk confetti, a red card that flips in, the fourth official's LED substitution board, and a change-of-shape card
- **VAR offside lines**: for every goal, the offside check at the final pass is computed from the positions (second-last defender, never behind the ball) and drawn across the pitch, e.g. *VAR: onside by 1.1 m*
- **Stadium atmosphere**: a crowd synthesised in the browser from filtered noise (no recorded audio) that follows the Match Pulse, roars at goals, groans at big chances, and a referee's whistle
- **Shareable moments**: every insight exports as a 1080 x 1350 card (mini pitch with the AI's drawings, caption in the viewer's language and mode, VAR badge), ready for social feeds
- **Weather**: the match sheet says light rain, so it rains under the floodlights

## The synthetic data

`MatchSimulator(seed)` produces a full 90+ minute match from one integer.
Storylines come from a **script of tactical beats** (a high press at 15', a
switch to 4-2-3-1 at 65', a red card at 76'...). Coaching intentions are never
written into the event stream: the Spotter has to discover them from the data,
and the script is saved separately as ground truth so we can test that it does.

Realism across seeds (see `tests/test_engine.py`):

| Metric | CHALK generator | Typical real range |
|---|---|---|
| Events per match | 2,000-2,300 | ~2,000-3,000 |
| Passes | 870-990 | ~800-1,100 |
| Pass accuracy | 81-84% | ~75-88% |
| Shots | 14-24 | ~20-28 |
| Total xG | 1.7-3.4 | ~1.0-3.5 |

**Demo match (seed 4):** Ashvale Rovers 3-2 Kestrel Bay FC. Ashvale's high press
puts them 2-0 up, Kestrel come back to 2-2 with counters and a formation change,
go down to ten men, and concede an 89th-minute winner. Analysis runs at about
11 microseconds per event.

| Scripted beat (ground truth) | Found by the Spotter from data alone |
|---|---|
| 15' Ashvale start a high press | 20' `press_surge` (Ashvale), goals at 26' and 29' |
| 30' Kestrel drop into a low block and counter | 37' `press_surge` (Kestrel), 40' goal |
| 65' Kestrel switch to 4-2-3-1 and press higher | 66' `tactical_shift`, 67' `press_surge` |
| 76' Kestrel red card | 77' `red_card` |
| 78' Ashvale throw everything forward | 80' `momentum_swing`, 84' `press_surge`, 89' winner |

## Run it

Python 3.10+.

```bash
pip install -r requirements.txt
python scripts/generate_match.py          # writes data/match_4*.json(l)
python scripts/run_pundit.py              # the AI crew (see above)
python -m pytest -q                        # tests
python scripts/serve.py                    # opens the replay at http://localhost:8000/web/
uvicorn chalk.server:app --port 8000       # or the live server (adds "Watch live")
```

The replay has two cameras: **Broadcast** (a perspective view from a high
gantry, like a TV tactics camera) and **Tactical** (flat, top-down). Switching
between them animates the camera move.

**Explainable by design:** every insight has a **Why?** button. It opens the Studio crew
panel: each claim with the exact facts behind it, every VAR verdict (including what it
overturned and why), how many drawings VAR rejected, and how long each agent took.

In the replay: Space plays and pauses (and resumes after an insight), the arrow keys skip 15 seconds, the Match
Pulse ribbon is a scrubber, and selecting a key moment jumps to just before it.

```
web/                 the app: index.html, style.css, pitch.js (renderer), app.js (playback, live feed),

tests/
data/                generated match files
```
